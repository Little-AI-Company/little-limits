# Apple design principles

Reviewed against the live HIG on October 13, 2026. Apple reintroduced eight principles in June 2026. Use them to weigh a decision, not to assign a product score.

| Principle | Question for AI Usage Stats |
| --- | --- |
| Purpose | Can someone quickly understand available Claude and Codex usage for the intended account? |
| Agency | Can someone control refresh and account setup, cancel sign-in, and recover without losing account selection or manual edits? |
| Responsibility | Does the app preserve private account data and show unknown, failed, and stale readings honestly? |
| Familiarity | Do menus, commands, sheets, focus, and window behavior work like ordinary macOS controls? |
| Flexibility | Does the affected task work with supported window sizes, keyboard and assistive input, and display preferences? |
| Simplicity | Does each visible control or reading help the immediate decision, with longer explanations available on demand? |
| Craft | Are identities, units, alignment, dates, labels, and transitions consistent in normal and failure states? |
| Delight | Does prompt, stable, quiet behavior make the utility pleasant without decoration or continuous motion? |

The product's main task is monitoring, so prioritize accurate readings, stable identity, low effort, and restrained resource use. Keep names consistent across menu commands, account headings, settings, details, tooltips, and spoken output. Do not introduce search, agent controls, content generation, or new system integrations merely to exercise a principle.

Sources: [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles), [Writing](https://developer.apple.com/design/human-interface-guidelines/writing), [What's new in design](https://developer.apple.com/design/whats-new/).

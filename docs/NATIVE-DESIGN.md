# Native design

Limits Left is an AppKit menu bar utility. A status item opens one standard native menu for first run and connected accounts. One native window handles Home, account pages, account setup, Claude Platform connections, and Settings. Subscription sign-in uses an attached sheet and the external browser. `LSUIElement` keeps menu-only use out of the Dock. Opening the management window promotes the app to regular activation so Command-Tab can return to it after another app takes focus. Minimized windows remain open; closing the window returns the app to accessory activation after any attached sheet ends. Command-W closes the window, Command-M minimizes it, and reopening restores the same window.

The window is an `NSSplitViewController` with a collapsible sidebar item (`sidebarWithViewController:`, full-height layout, 200 to 340 point width) and a content page, under a unified `NSToolbar` with `.fullSizeContentView`. The packaging script records the build SDK in the binary (`-platform_version macos 14.0 <SDK>`); SwiftPM alone records SDK 14.0, which keeps the pre-Liquid Glass appearance on current macOS. Liquid Glass sidebar and toolbar materials need the binary linked against the current SDK, so judge appearance only from the packaged app. On macOS 27.0.1, captured inactive windows, Finder and Music included, show a full-height, edge-to-edge sidebar; this app matches the system. Minimum deployment stays macOS 14. See [RELEASING.md](RELEASING.md).

## Vocabulary

One name per concept in every surface: status item, status menu, sidebar, Home, calendar, popover, account page, alerts, tooltips, and accessibility text. Adopted after the [2026-10-14 crit](design/crits/2026-10-14-baseline.md) (HOME-08).

| Concept | Use | Do not use |
| --- | --- | --- |
| Subscription quota percentage | Remaining: `51% left` (`InterfaceFormatting.remaining`); on one line, a comma before the state word: `17% left, Low`, `0% left, Limit reached` | `used`, `remaining` as a value suffix, `17% left Low` |
| Usage windows | `5-hour`, `Weekly`, model-scoped `Weekly · Fable 5` | `5 hours`, `7 days`, `Model limit`, `Fable 5 weekly`, `Weekly (Fable 5)` |
| Unknown reset | `Reset time unknown` | `Reset unknown`, `Time unavailable` |
| Measured zero use with no reset time, on a current reading | `No reset pending`; an outdated reading keeps `Reset time unknown` | `Reset time unknown`, `Reset due`, a zero countdown |
| Pooled weekly quota | `175% of 200% left`, beside it `1 account unknown`; an all-unknown total is `Unknown` | `0%` for unknown, `175% / 200% remaining` |
| Next pooled reset | `Next reset`, value `+25%`, timing `in 3d 0h` | `Reset gain`, `+25% left` |
| Exhausted account | `Usable in 2d 0h`, `Usable time unknown` | `Back in`, `Available in` |
| Weekly pace | `Ahead of pace`, `On pace`, `Under pace` | `Behind`, `Over budget` |
| Codex reset grants | `Earned resets`, value `2 available`, timing `Next expires in 12d` | `Quota resets`, `Quota reset` |
| Old earned reset count | `Last known 2 available`, in the menu, Home, and the account page | `Last known 2`, a bare count with no unit |
| Failed authentication | State `Sign-in required`, command `Reconnect…`, recovery text `Reconnect this account.` | `Subscription access required`, `Sign-in is required before…`, `Connect this account again.` |
| Old reading | Value prefix `Last known` (on Home, its own line above the value), state `Stale · last read 11:09`; the same in the menu, Home, and the account page | `Usage stale`, `Stale usage reading`, `Stale historical reading`, an outdated value without the prefix |
| No reading | `Unavailable`, with the reason in the tooltip, in every cell, status, attention line, and menu state line | `Usage unavailable.` without a reason, `No usage data`, `Unknown` or `No reading` for an account never read |
| Provider does not report a value | `Not supported` in secondary label color | bold `Not supported`, `Not applicable` |
| Claude API billing | `API Credits`; the sign-in site is `Claude Platform` | `Claude Console`, `API billing`, `Platform sign-in`, `Manage Claude Platform…` |
| Refresh every account | `Refresh All` (Command-R), recovery text `Refresh to read current usage.` | `Refresh`, `Check Usage`, `Check usage again` |
| Refresh one account | `Refresh Account` (Shift-Command-R) on the account page | `Refresh`, `Refresh Quota` |
| Selected account commands | File menu `Reconnect…`, `Open Billing`, `Delete Account…`; menu row `Open Account` | `Open Account…` |
| Delete an account | Use `Delete` | Do not use `Remove Account` |
| Open the window | `Open Limits Left` | `Manage Accounts…` |
| App settings | Command `Settings…`, page title `Settings` | `App Settings`, a gear-only entry point |
| Add an account | `Add Claude Account…`, `Add Codex Account…`; keep the verb through the flow | `Connect Claude…` then `Sign In…` |

Page headings use title case. Error text says what happened and what to do next.

## First run

Use an actual `NSMenu` with direct Add Claude Account… and Add Codex Account… commands, a separator, then Open Limits Left, Settings… (Command-comma), and Quit. There is no Refresh All command until an account exists. AppKit owns its appearance, keyboard selection, sizing, and dismissal. Explain Claude browser sign-in and Codex CLI sign-in in the add-account sheet, rather than a technical paragraph in the menu.

Do not show a title banner, disabled Refresh control, generic Actions dropdown, empty dashboard, or refresh footer. A load failure shows `Accounts could not be loaded` as an enabled line that opens the window, where Home explains the failure, with the cause in its tooltip, and a Retry Loading Accounts command; it is not treated as a fresh account list. After removing the last account, the next ordinary click returns to this menu.

## Account usage menu

Use the actual status item's `NSMenu` for populated accounts. Each account begins with `NSMenuItem.sectionHeader(title:)`, available on macOS 14, displaying a 16-point provider logo, provider name, and verified email, such as `Claude • personal@example.invalid`. This native gray section label is an explicit exception to the general restriction on gray subtitles. When email is absent, show the saved account name and put `Email unavailable` in its tooltip. Missing email does not imply an unverified account identity. Never present an alias or account identifier as a verified email. Preserve stored account order and separate each account with a standard menu separator.

When a provider has two or more accounts, the menu begins with one `Claude • All accounts` or `Codex • All accounts` section header per provider, Claude first, followed by text rows with the same tab stops as the account rows: `Weekly` with the pooled total (`175% of 200% left`) and the unknown count (`1 account unknown`), one `Weekly · <model>` row per model or named weekly window, and `Next reset` (`+25%`, `in 3d 0h`). The rules are in Home reset calendar below. These rows open Home; their tooltips name the counted and uncounted accounts and the exact reset. No chart, bar, or custom view appears in the menu. An account with a fully used current 5-hour or weekly window adds `Usable in` (`2d 0h`, `Sat 11:50`), or `Usable time unknown`, after its usage rows; a full model-scoped limit restricts only that model and adds nothing.

Order inside an account section: heading, then the state line when the reading is not current (`Sign-in required`, `Stale · last read 11:09`, `Unavailable`, `Observation time unknown`; an account with no reading has `Unavailable` and no reading rows) and an `API Credits need attention` line when a Claude Platform message exists, then the readings, then one recovery command. The state line and the attention line are enabled items that open that account, so AppKit draws them at label contrast; the full explanation is in the tooltip. Disabled items carry only unavailable commands and transient progress (`Loading Accounts…`, `Saving account…`), never a state or error. The recovery command is `Reconnect…` when sign-in is required and `Open Account` for other states; it appears only when a state line or attention line appears. The status menu does not autoenable items, so Reconnect… is validated with the window's rule and is disabled in demo mode, during a refresh or account change, and while a window sheet is open.

Readings are enabled menu items that open that account in the window, routed by account UUID. They use no explicit colors, so AppKit draws label color and the highlight. Use no custom menu views, progress bars, cards, pills, dashboard controls, or custom backgrounds. Indent data beneath each heading. Native attributed titles use shared tab stops to align compact labels, semibold values, and secondary timing: `5-hour   12% left, Low   Resets in 1h 1m`. Values use remaining quota with `Low` (20% or less) or `Limit reached` (0%). When the reading is outdated (stale, sign-in required, a passed reset, or older than five minutes), the value is `Last known 63% left` and the timing is omitted for sign-in required. `InterfaceFormatting.reading` supplies this value and timing to both the menu and the account page. Weekly and model-scoped readings use the same meaning. Credit rows appear only for balances with a reported amount, a status, an observation time, or manual entry; unconnected placeholders belong on the account page. A Codex account has one `Earned resets` row (`2 available`, `Next expires in 12d`); per-grant expiry stays in the tooltip. The account page uses the same row from `InterfaceFormatting.earnedResets`, not one generic credit row per grant. A stale account page ends its state line with `Choose Refresh Account to read it again.`; Connection Details shows one expiry line per credit and date, and labels a stale explanation `Status:`. The Models page says a small sample once, in the page note, with `(under 5,000)` after the model name. Retain known expiry, manual status, financial units, and at most one concise usage state plus one Platform attention row. The compact status-item summary retains its remaining-capacity meaning. It shows only provider template logos and percentages, with no written provider names; full names and quota meaning remain in tooltip and accessibility text.

Keep subscription quota, API money, Codex credit units, and earned reset counts separate. Preserve unknown values, inactive quotas, reset countdowns, expiry, original grant amounts, manual labels, stale readings, authentication failures, and recovery instructions. Freshness and provider details remain available in native item tooltips and the account page's Connection Details. Exact dates include the time zone. The commands are Refresh All (Command-R), Open Limits Left, Settings… (Command-comma), and Quit. Refresh All is disabled in demo mode and while a refresh or account change runs.

Build the menu's current readings and countdowns immediately before AppKit begins tracking. Keep that menu unchanged while open, including during provider refresh and account changes, so keyboard selection remains stable. The next opening applies current model data. There is no countdown repaint timer. AppKit supplies keyboard selection, scrolling for long menus, Escape, and outside-click dismissal.

## Compact status preview

Use one native status-item button with a composed template image: 14-point provider logos, 12-point monospaced percentages, a 3-point icon/value gap, and a 9-point gap between providers. The button title is empty when accounts exist. Unknown quota remains `?`, stale or sign-in state retains `!`, and no-account fallback is the talking-gauge template glyph (`StatusItemImage.appGlyph`).

By default the item shows one number per provider: the lowest remaining quota across that provider's accounts. The number is the lowest remaining percentage among each account's general 5-hour and weekly windows; a model-scoped limit restricts only that model and is shown as a menu row, never in the status item number. The status menu's Show in Menu Bar submenu starts with Lowest per Provider (checked by default), then one item per account; the sidebar context menu has the same per-account toggle. Checking accounts gives each checked account its own logo and number, in sidebar order, and only those accounts affect the `!` mark; choosing Lowest per Provider returns to the default. The choice is a display preference stored outside account data (`MenuBarAccountIDs` in user defaults, not persisted in demo mode); the earlier `MenuBarHiddenAccountIDs` value is read once and converted. With every account unchecked the item shows the app glyph. For each group (a provider, or one chosen account), show the lowest remaining quota among its accounts with a current reading (`AccountQuotaSummary.lowestCurrent`): state available, observed under five minutes ago, no passed reset, and every current window measured. A non-current reading never replaces a current one. When a provider has no current reading, it shows its lowest last known value (`AccountQuotaSummary.lowestLastKnown`: any measured general 5-hour or weekly window with a trustworthy observation time) and the item carries `!`, so a wake or an outage keeps the number instead of `?`. `?` means the provider was never measured. The tooltip and accessibility value name the account and window behind each number (`Codex: 0% left on codex@example.invalid, 5-hour`), count accounts left out, and, when no reading is current, give the last known value with its account and window and list each account's state. A typed summary of provider, remaining percentage, and stale state is compared with the displayed summary before drawing; unchanged refresh results do not recreate the image. Draw 1x and 2x bitmap representations once per changed summary. The final image is a template so the native button supplies light, dark, and selected tint. The same shared ProviderIcons loader supplies account headings and the preview.

## Provider logo resources

The Claude asterisk and OpenAI knot used for Codex come from the local opencode UI assets, with their source SVGs preserved alongside offline-rendered transparent PNGs. AppKit displays the PNG alpha silhouettes as template menu images. On macOS 27+, request `preferredImageVisibility = .visible` because AppKit otherwise typically hides menu-item images. This availability check leaves the macOS 14 deployment target intact.

SwiftPM includes the ProviderIcons resource directory. Packaging copies its generated resource bundle into the app's Contents/Resources. Loading first discovers that bundle through Bundle.main; Bundle.module is a lazy fallback for SwiftPM development. The bundle includes the opencode MIT license, copyright, original source paths, and source commit in NOTICE.txt. Packaging and runtime need no SVG renderer. See [RELEASING.md](RELEASING.md).

## System controls and appearance

`NSMenu` owns status-item presentation and tracking in every account state. Use standard AppKit controls and system appearance for the single window and its Settings page. System components handle Reduce Transparency, Increase Contrast, and Reduce Motion. The app adds no custom spatial animation.

The app-only `--increase-contrast` launch flag selects a high-contrast appearance without changing system settings; it does not establish that a real preference transition was tested. `--dark-appearance` requests the app's dark appearance for validation. The runtime target remains macOS 14+. Building requires Swift 6; the current verification environment uses the macOS 27 SDK and Swift 6.4, and the packaging script links against that SDK. Older runtime execution remains unverified.

Appearance and accessibility results belong in [VALIDATION.md](VALIDATION.md).

## Account editing

The window uses a sidebar for stable account selection: a Home row, a Models row, one two-line row per account, and native plus and minus buttons below the list. Line 1 is the provider template logo and the identity, which truncates at the tail only when it is longer than the sidebar. When two saved accounts show the same identity, the sidebar row and the account page window title prefix the provider (`Claude · personal@example.invalid`), as the status menu heading does; at the 260 point default the email tail may then truncate, and the tooltip keeps it whole. Line 2 is the state symbol and the quota summary in label color: remaining quota, the state word, and the limiting window (`51% left · Weekly · Fable 5`, `17% left, Low · Weekly`, `0% left, Limit reached · 5-hour`); it truncates at the tail. `Low` means the lowest current quota has 20% or less remaining and `Limit reached` means 0%. State symbols match the table and calendar and differ in shape: `exclamationmark.triangle.fill` (Low), `exclamationmark.octagon.fill` (Limit reached), `person.crop.circle.badge.exclamationmark.fill` (Sign-in required), and a secondary-color `clock` (Stale). Low and Limit reached use one color per state in every surface (`StateSymbolColor`, through `HomeReadingTone.symbolColor`): the table, calendar, popover, and sidebar. Light appearance darkens the system orange and red so each symbol reaches 3:1 on white and on the sidebar. On an emphasized selection the sidebar symbol takes the selected text color, as the calendar does; its shape keeps the state. The Home and Models rows follow the system sidebar row height; account rows add one quota line. The default sidebar width is 260 points. Unknown, inactive, stale, unavailable, and sign-in states show words instead of a percentage. A percentage appears only when every active window has a finite value and a known, current observation time. Expired resets and readings at least five minutes old are stale. Credits do not affect quota text. The tooltip and accessibility label identify the account, limiting window, and last observation; unchanged display values do not reload the table. The sidebar can be resized and collapsed with the toolbar toggle, View > Show Sidebar (Control-Command-S), or dragging.

Plus opens the add-account sheet (`AddAccountSheetController`): a provider pop-up button, a short explanation of that provider's sign-in, and Cancel and Continue at the trailing edge, with Continue as the Return default. The sheet is 380 points of text wide and takes its height from the fitted content for the chosen provider. File > Add Account… (Command-N) opens the same sheet. The verb stays `Add … Account` from the menu through the sign-in dialog. Minus removes the selected account only after confirmation and is disabled on Home, Models, Settings, and empty or busy states. Accounts reorder by dragging rows in the sidebar (native table drag with a gap, Home and Models stay first), or with File and context menu Move Up and Move Down (Option-Command-Up and Down); both are blocked in demo mode and while accounts change, and the order is saved. The sidebar context menu (Delete) and Delete key retain the same UUID-bound confirmation.

The account page is `AccountDetailViewController`. Its toolbar items are Reconnect…, Billing, Refresh Account, and Refresh All, after the sidebar tracking separator. Refresh Account and File > Refresh Account (Shift-Command-R) read only this account again; they share the refresh state with Refresh All, so neither runs while the other does, and both are disabled in demo mode and during account changes. Usage rows show the countdown and the short absolute time together (`Resets in 2d 4h · Fri 13:43`). File > Reconnect…, Open Billing, and Delete Account… send `reconnectSelectedAccount(_:)`, `openSelectedAccountBilling(_:)`, and `removeSelectedAccount(_:)` with a nil target. Reconnect and Delete validate like the Reconnect toolbar item and the minus button; Open Billing validates like the Billing toolbar item and reaches the account page while focus is in the sidebar. Refresh All refreshes every account and is labeled so. The window title is the account identity. The page is a scroll view that leads with aligned Usage and Credits rows, prominent values, and short reset and expiry timing. One state line carries at most one recovery action: Reconnect… for failed sign-in, or Allow Keychain Access… only when the failure is a Keychain read. Connect or Manage API Credits and connected-only Disconnect API Credits sit beside Credits. Inline, selectable Connection Details keep account identity, verified email, reported plan, configuration path where applicable, observation time, exact reset and expiry dates, source descriptions, and errors. Allow Keychain Access reads the existing saved credential and may show a system permission dialog; it does not reconnect automatically. API-credit disconnection retains the isolated Platform sign-in and saved manual balances. Manual balance remains collapsed until needed.

Settings is reached from Settings… in the status menu or app menu, or Command-comma. It has no sidebar entry. The page is titled `Settings`, holds a Startup row with Launch at login and an App icon row, and moves keyboard focus to that checkbox. Reading startup state does not register or unregister a login item. App icon is a pop-up button (VoiceOver label `App icon`) with Enamel, the default, and Night, each item showing its 16-point icon. One line under it says what the choice changes. The choice is stored as `AppIconChoice` in user defaults (not persisted in demo mode) and applied at launch through `NSApp.applicationIconImage`, so Night shows in the Dock and app switcher while the window is open and in About Limits Left, which receives the icon explicitly because the standard panel otherwise shows the bundle icon. The bundle icon stays Enamel, so Finder, Launchpad, Login Items, and the Applications folder keep Enamel. macOS has no alternate icon API for Mac apps, and `NSWorkspace.setIcon(_:forFile:)` on the bundle adds a Finder info attribute and an `Icon` file that fail `codesign --verify --strict`, and a reinstall or Homebrew upgrade would drop it. Returning to the same account preserves unfinished manual edits. Subscription confirmation and ordinary dialogs remain attached sheets; OAuth callback and account guards remain unchanged. The app menu has About, Settings…, Hide, Hide Others, Show All, and Quit; the Window menu has Zoom.

The window has one size range across Home, account pages, Settings, and Platform: 1020 × 640 point minimum, 1280 × 780 point default, and 1680 × 1040 point maximum content size. Initial placement fits the available screen. Navigation preserves the current frame and user resize; content scrolls when needed. Native Zoom uses the shared caps.

The Manual balance disclosure has persistent field labels for Category, Amount, Confirmed, and optional expiration. Automatic provider readings remain distinct from stored manual fallback records. Refresh must preserve an unfinished edit and the selected category. Delete remains separate from routine Save actions and uses the existing confirmation.

Credit formatting uses the same unknown-amount rule in the menu, account readings, and details: an available grant without a reported amount shows Unknown. This does not change measured zero, Unlimited, failure labels, or units. Claude’s unavailable API balances and grants explain the separate Platform connection; OpenAI API balances explain manual entry.

The experimental Claude Platform connection uses an embedded browser pane inside the window for official sign-in and its isolated billing session. The monitoring interface remains native. Keep organization selection, experimental status, authentication failure, and the recovery action understandable. Connect API Credits… makes monthly-grant setup explicit and names platform.claude.com authentication as separate from Claude subscription sign-in at claude.ai. Passkeys and security keys cannot work in this embedded view: Apple allows WebAuthn in a WKWebView only for the app's own associated domains, and the browser entitlement is limited to web browsers. The sign-in instruction therefore tells people to choose Try another way and use a password or code. The compact native wrapper has Back, one account context and instruction, and one primary Continue/Connect/Refresh Credits action; choosing a different saved organization explicitly says Switch Organization. The labeled organization picker appears only after organizations are discovered; Connect requires a valid selection. Reload Sign-in, on-demand details, and connected-only Disconnect live in a Connection menu. Short status messages retain full errors/dates in tooltips and details. The per-profile Platform controller is embedded in the existing detail area with Back, which preserves the selected account and unfinished edits; choosing the selected account row in the sidebar also returns to the account page. An interactive read may return to the overview only while its pane is visible, supplemental fetches succeeded, and the discovered nonempty Platform email matches the verified Claude email after trimming and case-insensitive comparison; other/unknown logins keep their explicit context and Back; background refresh never navigates the user or reveals the browser. Provider navigation does not probe or connect automatically. The same window keeps its current size for the browser and on Back. Closing it pauses/parks the visible browser without changing its persistent WebKit session. An empty account list shows Add Claude Account… and Add Codex Account… buttons instead of opening Settings. The Platform page is titled with the account identity and subtitled `API Credits`. The Claude sign-in dialog is a sheet with a single Cancel button. A successful sign-in closes the sheet and opens the connected account's page, which states whether usage was read; a failure keeps the sheet with its message and a Return default Close. No separate Settings or Platform window is retained. When the provider reports an eligible plan as Not linked, the existing billing command opens Claude Settings > Billing for human linking or claiming; the app performs only reads. The same isolated Platform session reads selected-organization balance, plan linkage, and invoices, preserving invoice query parameters. Supplemental failures preserve good purchased balances and a visibly stale, dated last verified monthly reading. Unrelated promotions cannot suppress a monthly placeholder or saved manual fallback.

## Models page

Models is the second sidebar row (`ModelsViewController`, a SwiftUI `ModelsView` in `NSHostingView`). It shows behavior metrics per model from the local usage history, never per account: a Claude section and a Codex section, each with one block per metric (M1 to M9, P1 to P5 in [USAGE-ANALYTICS-PLAN.md](USAGE-ANALYTICS-PLAN.md)). A block lists each model with a bar, its exact value, and the counts behind it; shares use a fixed 0 to 100 percent track, and other values scale to the largest model. Unknown values read `No data` or `No commits`, never 0. Models are named as the rest of the app names them, one name per concept: `InterfaceFormatting.modelDisplayName` turns `claude-fable-5-1` into `Fable 5.1` and `gpt-6.1-sol` into `GPT-6.1 Sol`, and shows an identifier in no known pattern as logged; the tooltip and VoiceOver value keep the raw identifier. Bars are drawn in primary color on the quaternary track, which keeps 3:1 in normal and increased contrast. Models with fewer than 5,000 requests keep full-strength label text (no opacity on text, so 4.5:1 holds) and add `(under 5,000)` to the name, so the state is words, not color; one line at the top says why, and VoiceOver and the tooltip add the same note. Footnotes under a block carry the definitions: approximate output speed (compare within one provider), shell searches only for grep, and the Codex parallel tool call rule. The window title is `Models` and the subtitle gives the date range of the history. With no history the page shows one line; a database that cannot be opened shows its error. The page has no controls, so focus stays in the sidebar. Demo mode reads fictional rows from a temporary database, never the user's history. `--show-home --show-models` opens the page for inspection.

## Home reset calendar

Home is the first sidebar row and the default view when Open Limits Left opens the window. Dock reopening preserves the active screen. All pages share the window size range described above; selecting Home does not resize the window.

Home is one scroll view. Weekly Totals comes first when a provider has two or more accounts: a text grid with the provider logo and name on the first row of each provider, `Weekly` and one `Weekly · <model>` row per model or named weekly window, and `Next reset`. A total sums remaining quota (100 minus used) over accounts with a current reading of that window: available, observed under five minutes ago, that window's own reset not passed, and a measured value. Another window's passed reset after the reading does not remove the account from this total. A reading marked stale never counts, even when recent: a failed refresh keeps the last observation time, and a reader marks a reading stale when a reset had already passed when it was read; the next refresh, at most five minutes later, replaces it. A current reading with no active weekly window reports none, so that account is outside the total rather than unknown; when no account reports the window, the total reads `Not supported`. A scoped weekly limit without a model name (`limit_<n>_weekly_scoped`) is never the general weekly window. Stale, sign-in-required, failed, unread, and unmeasured accounts are left out of the total and its capacity and counted beside it (`75% of 100% left`, `1 account unknown`); a last known value never counts. With no counted account the total is `Unknown`. Claude and Codex are never combined. A model total covers only accounts whose latest reading reports that window active; an account that never reported it, or reported it inactive, is outside that total rather than unknown. `Next reset` is the earliest weekly reset among counted accounts that returns quota, and its value is that account's used percentage; it is `Unknown` when any counted account has used quota without a future reset time, since that reset could come first, `No reset pending` when every counted account has used none, and `Unknown` when no account is counted. Totals pool every account regardless of the account filter. The calculations are pure functions in `UsageCore/QuotaOverview.swift`.

Home order: Weekly Totals, Account Usage, Forecast, Reset Calendar. Each period command (Previous, Next, Today, Month, 2 Weeks) also scrolls the Reset Calendar heading to the top of the visible area, without animation, unless the heading already shows with a row of days; the account filter does not scroll, because it also changes the visible table. Forecast labels read `Usage rate` and `Weekly total reaches 0%`, and both provider blocks share one label column width. Chart marks use the primary label color, not the accent. Home recalculates the key view loop after each render. Updated column: last read time when known, with `Not refreshed` or `Stale`; else `Unavailable`. Do not use `No reading`.

The Account Usage table follows at its intrinsic height, with fitting columns and short secondary text (`Resets today 13:43`); the Forecast follows it, then the Reset Calendar. Quota text is label color. A quota cell reads the value with its state symbol (`0% left`), then `Low` or `Limit reached` on its own line, then the reset time. Lines above the value name the window in a shared Other limits column (`Weekly · Fable 5`) and qualify an outdated value (`Last known`), so the value stays whole. A sign-in-required account keeps its last known values without reset times; the accessibility label reads `0% left, Limit reached, resets …`. At the minimum window, quota text stays whole for current, stale, sign-in, and missing readings (`HomeLayoutTests` covers both demo fixtures); the Earned resets cell gives an old count's read time as `Last read 15:00`; a long email in the Account column truncates with the full text in its tooltip. A line above the table names each account that needs attention and its state. A current Weekly cell adds a pace line: `Ahead of pace` when the used percentage exceeds the elapsed share of the window by more than 5 points, `Under pace` when it is more than 5 points below, otherwise `On pace`; the elapsed share is the window length minus the time to reset, so a window without a known length or future reset has no pace line. An account with a fully used current 5-hour or weekly window shows `Usable in 2d 0h` in the Account column, the latest reset among those fully used windows, or `Usable time unknown` when one has no reset time or another general window is unmeasured. Model-scoped and named limits never decide usability, and a passed model reset does not make the account's usability outdated: such a row reads `Stale · last read 11:09 · Usable in 2h 0m`, matching the menu's `Usable in` row. View > Sort Accounts orders the table: Saved Order (default), Most Remaining (each account's limiting window), or Soonest Usable (usable now, then exhausted accounts by usable time, then unknown). Ties and accounts without a current reading keep saved order, so an unchanged refresh never moves a row; the order lasts until the app quits and does not change the sidebar or the menu. Permanent provider gaps (`Not supported`) use secondary label color at regular weight and read the same in every reading state, including Claude earned resets while sign-in is required.

The toolbar holds Previous and Next, Today, an account filter pop-up button, a Month and 2 Weeks group, and Refresh All, with the window title `Home` and the displayed period as subtitle. These items come from `WindowToolbarContributor`; each page supplies its own items, title, and subtitle. The View menu has Show Sidebar, Month (Command-1), 2 Weeks (Command-2), Previous (Command-[), Next (Command-]), and Today (Command-T); View > Show Account lists All Accounts and each account, checked like the toolbar filter, and applies only while Home shows. The File menu has Add Account… (Command-N). Period commands reach the visible page through the responder chain. When readings show, focus starts on the sidebar Home row rather than on a calendar event, so nothing on the page looks selected on arrival; Tab reaches the table and events after it. Empty and load-failure pages focus Add Claude Account… or Retry.

The calendar is Monday-first, two weeks or a month. Each event is two single-line rows. Row 1: provider icon, reset time, then the scope (`13:11 · 5-hour`, `13:11 · Weekly`); a model-scoped or named window shows only its model or meter name (`14:18 · Fable 5`), so it never truncates to look like the account's general weekly reset, and the tooltip, accessibility label, and popover keep `Weekly · Fable 5`; the section title says these are resets, so the event omits the word and the tooltip and accessibility label keep it. Row 2: state symbol, remaining percentage, then the short account identity (`17% left · personal`). The time and percentage are never truncated; the scope and identity truncate. The slot height comes from the fitted text, and a week row grows to its busiest day. Short identities are distinct within a provider; full identity and exact time remain in accessibility text and the anchored native popover. Events come only from current, active windows with finite measured percentages and future reset dates. Readings at least five minutes old, missing or future observation times, failed authentication, unavailable snapshots, or a passed current quota reset exclude that account from the calendar. A missing percentage excludes that window while other known windows remain visible.

Click or Return opens the account popover on the trailing edge of the event, away from the sidebar; hover shows only a tooltip. Escape and outside clicks dismiss it. View Account uses the existing UUID-bound sidebar route. The native account table has no nested vertical scroller; its columns share the width, fit the minimum window, remain user-resizable, and preserve saved order, selection, and scroll position across unchanged readings. Account filtering applies to the table and calendar. Model and named additional meters retain their scope. Plan names are reported metadata; Max and Pro do not imply a 20x multiplier.

Keep current, historical, unknown, inactive, unavailable, and sign-in states explicit. Measured zero alone says Limit reached. Earned reset count uses its own observation time; a known earned reset expiry passing after that observation makes the count historical without subtracting from it. Earned reset expiry stays in the table and popover, separate from calendar quota resets and monetary balances. Empty and load-failure views show their setup or retry message without calendar controls; the empty view has Add Claude Account… and Add Codex Account… buttons and says `Add a Claude or Codex account to see remaining quota and reset times.` Demo fixtures disable provider refresh, reconnection, and account mutation.

`--show-home` and `--show-accounts` open Home. `--show-settings` opens Settings and `--show-about` opens About Limits Left. Pass `-AppIconChoice night` to try Night for one launch without saving it. `--demo` supplies a Claude and a Codex account that share one email, for the provider prefix; `--demo-home` supplies four fictional accounts; `--demo-reading-states` adds sign-in failure, stale, and missing readings. Either fixture flag enables demo isolation without an additional `--demo`. Existing empty/load-error flags take precedence. These flags support local verification and do not establish live-provider behavior.

## Interaction and accessibility

Test ordinary status-item clicks for populated and first-run menus, including arrow-key/Return selection of reading rows and commands, Escape, outside-click dismissal, provider-dialog cancellation, and account loading failure. Test reopening after the app becomes inactive, placement near screen edges, long/missing emails, and preservation of the selected command while a refresh completes.

Quotas, units, dates, unavailable readings, and errors have native text equivalents. Menu items retain exact values and dates in tooltips. Inline Connection Details on the account page supplies extended readings and recovery diagnostics through selectable native text and direct controls for keyboard access. Source text alone does not establish VoiceOver behavior.

Inspect light and dark appearances, Reduce Transparency, Increase Contrast, Reduce Motion, empty/error states, and keyboard navigation. Record which checks actually ran. `--show-menu` opens the real status menu; `--show-panel` remains an alias. `--show-home` and `--show-accounts` open Home in the window for inspection. The obsolete custom `--show-window` overview host is removed. A window capture or successful build does not prove menu-bar behavior or measured contrast.

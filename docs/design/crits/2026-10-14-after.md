`UX diagnostic 5/10 · HIG 7 pass, 10 fail, 8 untested, 0 N/A · Changes required · Worst open severity 3`

Method: the repository [crit skill](../../../.agents/skills/crit/SKILL.md), same as the [baseline report](2026-10-14-baseline.md) (revision 8e4f837), with independent UX heuristic and Apple HIG audits merged into one register. ## Verdict

Changes required. Worst open severity 3.

## What a first-time user experiences

Round 1 fixed 19 of the 28 baseline findings on screen and 6 more in source. The glance path is now honest: every surface says "51% left", status menu readings are full-contrast commands that open their account, failed accounts show their state and Reconnect… up front, and Home leads with the account table.

The window now looks like a macOS 27 app: a split-view sidebar with a toggle, a unified Liquid Glass toolbar with grouped navigation, view, and Refresh All, and a page title with the period as subtitle. The Liquid Glass look only appeared after fixing the packaging script, which had been recording SDK 14.0 in the binary.

One regression is severe: calendar events now wrap inside fixed-height slots, so reset times and percentages are cut through the letters. Smaller ones: sidebar identities are middle-truncated ("stud…valid"), "0% left, Limit reac…" truncates in the table, state lines in the menu are still dim, and a set of strings still breaks the new vocabulary.

## Proposed fix order

- **1. Calendar and table text.** Size calendar event rows to their wrapped text or keep each event to two fixed single-line rows; give the table state word room. Lane owns UsageCalendarView, UsageOverviewTableView. (HOME-12, HOME-14, EMPTY-03)
- **2. Sidebar rows.** Identity gets priority and a second line for quota and window; distinct state symbols at 3:1. Lane owns AccountSidebarCellView, AccountsWindowController. (HOME-13, HOME-05, HOME-16, HOME-04, PLATFORM-02)
- **3. Menu and vocabulary leftovers.** Enabled-looking state lines, separators, ellipsis rules, and the remaining glossary strings across InterfaceFormatting, UsageMenu, ClaudeConsoleClient, UsageService, DemoFixtures. (MENU-09, MENU-10, HOME-08, MENU-07)
- **4. Account page commands and add sheet.** Menu commands for Reconnect… and Billing…, and a sheet that sizes to its text. (ACCOUNT-04, ADD-ACCOUNT-03)

## Open findings

- **HOME-12** (severity 3, observed, nielsen.8, krug.dont-make-me-think, layout.native-adaptation) Calendar events wrap inside a fixed-height, clipped button that centers its text, so every event on Home shows times and percentages sliced mid-glyph. The calendar looks broken on first launch and the reset time, the fact HOME-07 moved to the front, cannot be read without opening the popover. **Fix:** Make both event lines single-line (maximumNumberOfLines = 1, usesSingleLineMode, truncate the scope words, never the time), or size the event slot from the fitted text height; pin the stack to the top instead of centerY. Measured: Day column about 140 pt; each event slot about 40 pt. '13:52 · 5-hour resets' wraps to two lines, so three lines exceed the slot; the reset time is cut through its top half and '0% left · codex' through its bottom half, in every day with an event, light, dark, and contrast. The first event's focus ring is clipped the same way. Source: `Sources/AIUsageStats/UsageCalendarView.swift:613-655`.
- **HOME-04** (severity 2, source, window.sidebar.native-glass, appearance.materials.hierarchy) The sidebar is a fixed 228 pt NSVisualEffectView with custom 66 pt three-line rows, not an NSSplitViewController sidebar. It does not float on Liquid Glass, cannot be hidden or resized, ignores the system sidebar size setting, and has no provider symbol per row. **Fix:** Build the window from NSSplitViewController with NSSplitViewItem(sidebarWithViewController:) (canCollapse, allowsFullHeightLayout) and standard source-list cells: provider template image, identity, trailing quota text. Remove the custom visual effect view and divider. Measured: Sidebar 228 pt fixed width, full height below a separate title bar, flat #E7EAEC panel with a 1 pt NSBox divider.; Account row pitch about 68 pt (66 pt row + 2 pt spacing); identity 13 pt, provider and quota 11 pt; Home row 32 pt with a secondary-gray house symbol. Source: `Sources/AIUsageStats/AccountsWindowController.swift:93-98,157-159,322-338; Sources/AIUsageStats/AccountSidebarCellView.swift:13-71; Sources/AIUsageStats/AccountsWindowController.swift:108-110,1069-1073`.
- **HOME-05** (severity 2, observed, krug.dont-make-me-think, nielsen.6) The sidebar says "personal 51% left" while the table beside it shows 99% (5-hour) and 75% (weekly); 51% is the Fable 5 model limit, named only in the tooltip and AX label. (three phrasings); five phrasings for stale; five names for Claude API billing (API Credits, Claude Platform, Claude Console, API billing, Platform sign-in); "Manage Accounts…" opens a window titled "AI Usage Stats". **Fix:** Write a one-page glossary and apply it: Earned resets, Model limit names as "Weekly · Fable 5" everywhere, "Reset time unknown", "Sign-in required", "Last known", "Refresh All", "Claude Platform". Rename the menu command to "Open AI Usage Stats…" or title the page Home. Source: `Sources/AIUsageStats/UsageOverviewTableView.swift:205`.
- **MENU-07** (severity 2, source, krug.dont-make-me-think, nielsen.6) The status item shows one number per provider, the lowest remaining across all accounts and all windows, including stale and sign-in-required snapshots. With the demo data the menu bar would read Codex 0% while work@ still has 63% left, so a user with several accounts reads "out of Codex" and cannot tell which account the number belongs to without opening the menu. **Fix:** Product decision. Either exclude non-current snapshots and show the best available account, or keep the lowest but name its account in the tooltip and the menu's first line. Not verified on screen because the status item glyph was not captured. Source: `Sources/AIUsageStats/ApplicationDelegate.swift:83`.

Measured: Default 1280 pt window, sidebar about 250 pt. - **MENU-09** (severity 2, measured, menu.commands.grouping, appearance.color.legibility) The account state rows, the most important message in a failed or stale section, are disabled menu items that AppKit draws at disabled contrast (2.25:1) despite the labelColor attribute, so the state now reads dimmer than the readings it qualifies. **Fix:** Put the state in the section: either append it to the header ("Claude • studio@… · Sign-in required") or fold it into the recovery command ("Reconnect… (Sign-in required)"), and drop the disabled row. Keep the full text in the tooltip. Measured: "Sign-in required" and "Stale · last read 12:04": #575757 on #202020 = 2.25:1 at 13 pt, identical to disabled Refresh All and the section headers; enabled readings and Reconnect… are 12.00:1. - **ADD-ACCOUNT-03** (severity 2, source, ) The sheet window is a fixed 420x180 pt, and the content stack is pinned with required equality constraints to the top and bottom (20 pt margins). The Claude explanation is about 220 characters at 12 pt in a 380 pt column (3 to 4 lines), so the title, picker row, text, and buttons need more than 140 pt of content height. The result is an unsatisfiable constraint, clipped text or a clipped button row. The sign-in sheet uses lessThanOrEqual for the bottom edge; this one does not. Not verified on screen. **Fix:** Pin the bottom with lessThanOrEqual (or size the window from the fitted content height) and confirm the sheet in the running app with both providers selected. Source: `Sources/AIUsageStats/AddAccountSheetController.swift:11,41-45,71-73`.
- **MENU-10** (severity 1, observed, menu.commands.grouping) "Open Account…" carries an ellipsis although it only opens the account page and asks for nothing, while "Open AI Usage Stats" in the same menu has none. **Fix:** Rename to "Open Account" without the ellipsis; keep "Reconnect…", which opens a sign-in sheet. Source: `Sources/AIUsageStats/UsageMenu.swift:79`.
- **EMPTY-03** (severity 1, observed, layout.native-adaptation) The empty and error pages show a vertical scroller with almost nothing on the page: the document is forced to at least the clip view height, and the automatic toolbar inset adds about 52 pt, so the page always scrolls by the toolbar height. **Fix:** Constrain the minimum document height to the clip view height minus scroll.contentInsets.top (or to the visible content rect), so a short page does not scroll. Measured: Vertical scroller visible at x 1985 to 1995 px across the full content height in light-empty-window.png and light-error-window.png with three lines of content. Source: `Sources/AIUsageStats/HomeViewController.swift:128-134`.
- **ACCOUNT-04** (severity 1, source, ) The account page toolbar items Reconnect… and Billing are text items with a private action on the page (target = self) and no menu command. The main menu has no Reconnect… or Billing entry, and no Remove Account… command either (remove is only the sidebar minus button, Delete key, and context menu). The toolbar is not customizable, so a narrow window overflows them into the chevron menu with no keyboard route. **Fix:** Add an Account menu or File items: Reconnect… , Open Billing, Remove Account… with nil-target actions the account page and window controller implement, and validate them against the selected account. Source: `Sources/AIUsageStats/AccountDetailViewController.swift:65-120; Sources/AIUsageStats/ApplicationDelegate.swift:373-416`.
- **PLATFORM-02** (severity 1, source, ) While the Platform pane is showing, the selected sidebar row is that account's row. Clicking that same row does not fire tableViewSelectionDidChange, so the page stays on the Platform pane. The only way out is the Back button in the pane. The same click leaves Settings, because Settings deselects the table. **Fix:** Handle clicks on the already selected row (tableView(_:shouldSelectRow:) or an action on the table) so choosing the account row returns to the account page from Platform. Source: `Sources/AIUsageStats/AccountsWindowController.swift:467-480,160-170`.

## Correct as designed

- Icon-only Refresh All in the toolbar is a standard toolbar item with tooltip and accessibility description 'Refresh All' (HomeViewController.swift:283,318); disabled in demo.
- Account Usage table placed above the Reset Calendar, with 'Remaining percentages from the latest reading · Times in CDT' below its heading, is label-color explanation, not a gray subtitle above a section.
- Disabled 'Add Claude Account…' and 'Add Codex Account…' on the empty page and in the empty menu are demo behavior.
- The full-height vertical scroller on empty and error pages follows the system scroll-bar setting; it does not indicate overflow.
- The secondary line 'Could not load accounts: Demonstration load failure.' under the plain-language body keeps the system cause available without leading with it.
- The menu is wider (about 495 pt) than baseline (about 401 pt) because value columns now hold 'Last known NN% left'; still one glance, and readings no longer need subtraction.
- Today toolbar button looks inactive because the shown period already contains today.
- #available: no unguarded macOS 26 or later API. Only NSMenuItem.preferredImageVisibility is newer, and it is guarded with #available(macOS 27, *) (UsageMenu.swift:46). Split view sidebar, toolbar style, subtitle, sidebarTrackingSeparator, NSToolbarItemGroup, and NSMenuItem.sectionHeader are macOS 14 or earlier.
- Enabled reading rows that open their account are acceptable menu semantics: each row is a command with the standard highlight and the text color AppKit supplies.
- Window title "Home" with subtitle period, account title equal to the identity, Settings title "Settings", and Platform subtitle "API Credits" follow the toolbar guidance and do not repeat the app name.
- Table secondary text ("Resets today 14:22") measures 3.85:1 light and 5.04:1 dark; it is system secondaryLabelColor and is not reported.
- Sidebar add and remove square buttons directly under the list follow the source-list convention; the toolbar holds no add or remove buttons.
- Add Account sheet button pair Cancel and Continue, with Continue as the Return default and Cancel on Escape, matches the Sheets guidance.
- Disabled Refresh All, Reconnect…, and add-account controls are demo-mode behavior.
- Documentation drift, not a UI defect: docs/NATIVE-DESIGN.md still says readings are noninteractive, shows "12% used", and names Manage Accounts…, which the shipped menu no longer matches.
- "Open AI Usage Stats" has no ellipsis because opening the window needs no further input.

## Limits

- No pointer input was available, so fixes made in source only are marked unverified. Their controls (account page, Settings, add-account sheet, sign-in sheet, Platform pane, empty-state add buttons) were not clicked.
- The HIG audit ran on the SDK 14 build, before the packaging script fix recorded the build SDK. The materials and sidebar outcomes (`appearance.materials.hierarchy`, `window.sidebar.native-glass`, `window.toolbar.grouping`) predate the Liquid Glass recapture and describe the pre-26 appearance.
- Status menu captures follow the dark system menu appearance; the app's `--dark-appearance` flag affects windows only.
- Captures use demo fixtures. They do not establish live-provider behavior.

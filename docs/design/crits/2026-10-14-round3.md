## Verdict

Review incomplete. No severity 3 or 4 finding is open; the worst open severity is 2. Ten fixes are unverified (source or tests only), and the keyboard, VoiceOver, display preference, and status item requirements are untested, because this environment has no pointer input or Accessibility access.

## What a first-time user experiences

Round 3 fixed the severity 3 calendar regression. Every targeted severity 2 finding is fixed or waiting only for a runtime check, except one vocabulary leftover (HOME-08). On Home, each calendar event is now two whole single-line rows, with the reset time first and no letters cut through. In the account table the state word sits on its own line ('0% left', then 'Limit reached'). Short empty and error pages no longer scroll.

The sidebar now answers 'which account is this' at a glance. Each account has its full email on line 1 and a second line that names the limiting window ('51% left · Weekly · Fable 5', '17% left, Low · Weekly'). The state symbols differ in shape and measure at least 3:1. The flat full-height sidebar matches Finder and Music on macOS 27.0.1, so HOME-04 is closed, with a key-window capture still to do.

In the status menu, state lines ('Sign-in required', 'Stale · last read 14:00', 'Accounts could not be loaded') draw at full contrast (12:1, up from 2.25:1) and open their account. 'Open Account' lost its ellipsis. A user still hesitates in three places. Model-specific calendar events read 'Weekly…', so Oct 20 shows two events that look the same. The Low triangle in the Home table and calendar is still 2.33:1 in light appearance. And one out-of-date reading reads three ways: 'Last known' in the menu, 'Unavailable' on Home, and as current on the account page.

One regression comes from the round 3 status item rule (MENU-07). The number now comes only from current readings, so a single-account user sees '?' whenever their only reading is more than 5 minutes old, for example after the Mac wakes. That loses the last known value the old '!' mark used to qualify.

## Proposed fix order

- **1. Model scope and Low color on Home.** Show the model name in model-scoped calendar events, for example '14:18 · Sonnet' with the full scope in the label and popover. Move the light-appearance state color from AccountSidebarCellView into a shared HomeReadingTone color so the table, calendar, popover, and sidebar all reach 3:1. UsageCalendarView, HomeInterfaceFormatting, AccountSidebarCellView. (HOME-17, HOME-18)
- **2. One out-of-date reading, one wording.** The account page uses lastKnownRemaining with no countdown for outdated readings. The Home table shows 'Last known NN% left' for sign-in-required cells. The no-reading state and the Other limits names follow the Vocabulary table. Put 'Last known' on its own line at the minimum window. AccountDetailViewController, HomeInterfaceFormatting, UsageOverviewTableView. (ACCOUNT-05, HOME-08, HOME-22)
- **3. Status item fallback and menu recovery.** When a provider has no current reading, show its lowest last-known value with the existing '!' mark, and keep '?' for a provider with no reading at all. Add a state line and 'Open Account' to no-reading menu sections. Validate the menu's Reconnect… with the window's rule. ApplicationDelegate, UsageMenu, AccountQuotaSummary. (MENU-12, MENU-13, MENU-14)
- **4. Identity and keyboard polish.** Prefix the provider name when two accounts share an email. Make the account table the first key view on Home. Give the sidebar state symbol the emphasized tint on a selected row. Add View > Show Account for the toolbar filter. AccountsWindowController, AccountSidebarCellView, HomeViewController, ApplicationDelegate. (HOME-19, HOME-20, HOME-21, HOME-23)

## Open findings

- **MENU-12** (severity 2, source, nielsen.1, nielsen.2) The status item now shows '?' whenever a provider has no reading under 5 minutes old, so a single-account user loses the last known number on the glance surface after every wake and during any outage, and '?' no longer tells 'never read' apart from 'read 6 minutes ago' while the menu still shows 'Last known 63% left'. New in round 3. **Fix:** Prefer the lowest current reading; when a provider has none, show its lowest last-known value with the existing '!' mark, and keep '?' for a provider with no reading at all. Measured: Refresh timer 300 s with 15 s tolerance; a reading becomes non-current at 300 s (AccountQuotaSummary.swift:25). model.refresh() calls onChange before fetching (ApplicationModel.swift:84-86), so after any sleep longer than 5 minutes, and for the whole of a network outage, every provider renders '?' plus '!'. Source: `Sources/AIUsageStats/ApplicationDelegate.swift:88-90`.
- **HOME-08** (severity 2, observed, krug.dont-make-me-think, nielsen.2, nielsen.4) The retired strings are gone, but two concepts still have several names: the Home table says 'Fable 5: 51% left' where the menu, sidebar, and calendar say 'Weekly · Fable 5', and one no-reading account is 'Unavailable' (sidebar), 'No usage data' (account cell and attention line), 'Unknown' (quota cells), and 'No reading' (Updated) on one screen, while table 'Unavailable' means sign-in failure. **Fix:** Name model-scoped windows 'Weekly · Fable 5' in the Other limits cells, and use 'Unavailable' with the reason in the tooltip for every no-reading cell; reserve 'Sign-in required' for sign-in failure. Stale earned resets use 'Next expires' like current ones. Source: `Sources/AIUsageStats/HomeInterfaceFormatting.swift:432-434,548-554,736; Sources/AIUsageStats/UsageMenu.swift:107; Sources/AIUsageStats/AccountDetailViewController.swift:407`.
- **HOME-17** (severity 2, observed, krug.dont-make-me-think, nielsen.6, nielsen.4, data.chart-legibility, layout.native-adaptation) Model-scoped calendar events lose the model name to tail truncation, so a Weekly · Sonnet or Weekly · Fable 5 reset reads "Weekly…" and is indistinguishable from the account's general weekly reset without hover or the popover; on Tue 20 the same account shows two events that look alike. ## Correct as designed

- Calendar events no longer say 'resets'. The time comes first, the section heading 'Reset Calendar' is on screen at the default window, and the tooltip and accessibility label keep the word. Month view, where the heading may scroll away, is untested.
- Sidebar quota text starts about 16 pt further right on rows with a state symbol than on rows without one; the state words carry the meaning and the identity line stays aligned.
- The page heading 'Accounts Could Not Be Loaded' is title case and the menu line 'Accounts could not be loaded' is sentence case; both follow doctrine (page headings title case, menu state lines as statements like 'Sign-in required').
- Attention lines name accounts by saved name ('Claude studio: Sign-in required. Choose Reconnect…') while the sidebar shows the email; the table row directly below shows both, so the mapping needs no recall.
- Table column headings 'Other limits' and 'Earned resets' are sentence case, matching the Vocabulary table spellings used as data labels in the menu.
- Countdowns keep a fixed two-unit form ('Resets in 3d 0h', 'Next expires in 12d 0h'), which keeps the timing column uniform.
- Toolbar 'Billing' is a noun while the File menu says 'Open Billing'; toolbar items may be nouns and the menu command carries the verb, per the Vocabulary table.
- Disabled Refresh All, Add Claude Account…, Add Codex Account…, and the Home Reconnect… button are demo behavior.
- Faint sidebar provider logos (light #BCBDBD on #ECEDEE, 1.61:1; dark 2.97:1) are the system's inactive-window treatment of untinted template images: the system-drawn Home house symbol measures 1.41:1 on its selection in the same capture. Key-window rendering untested.
- Sidebar stateColor maps the increased-contrast appearances to the darkened standard color instead of a system high-contrast variant; the result still exceeds 3:1 (4.34:1 and 6.07:1), so no defect, only an untested real-preference path.
- Enabled state lines that open their account are acceptable menu semantics and the documented design; AppKit draws them at label contrast and the highlight on hover.
- Native gray section headers at 2.25:1 are the documented exception (NATIVE-DESIGN.md Account usage menu).
- Availability: no new macOS 15 or later API in round 3. NSColor(name:dynamicProvider:) (10.15), performAsCurrentDrawingAppearance (11), NSStackView setViews(_:in:), effectiveRowSizeStyle, and NSAppearance.bestMatch are all within the macOS 14 target; the only newer API remains preferredImageVisibility under #available(macOS 27, *) (UsageMenu.swift:55).
- Swift 6 isolation: new statics (state colors, event fonts, preferredHeight) live on @MainActor types and the new NSMenuItemValidation conformances are main-actor; swift test builds and passes at d15aded.
- Home row selection, Retry focus ring, and toolbar Liquid Glass capsules are system drawn; the visible vertical scroller on Home is legitimate because the document is taller than the window.

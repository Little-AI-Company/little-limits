## Verdict

Changes required. One severity 3 finding is open (HOME-24): with history recorded, the forecast pushes the Account Usage table and the whole reset calendar below the default window. Seven severity 2 findings and six severity 1 findings are open. Keyboard, VoiceOver, real display preferences, plain light appearance, and the Platform pane remain untested.

## What a first-time user experiences

The status menu still answers the glance in one look: provider totals first, then one section per account with remaining quota and reset timing. The menu bar number is the one surprise. With the Home fixture the Claude number reads 51%. That is the Weekly · Fable 5 model limit, while the same account's 5-hour and general weekly windows have 99% and 75% left (MENU-16).

Home opens on Weekly Totals and then two forecast blocks, each about 227 pt tall. At the default 1280 × 780 pt window the Account Usage heading sits at 744 pt. The table and calendar are below the window, so the per-account answer needs a scroll. The toolbar Previous, Next, Today, Month, and 2 Weeks controls change a calendar the user cannot see (HOME-24). The forecast uses words found nowhere else in the app: Pool, Drain rate, Last seen (HOME-25).

Models is readable and dense. Two things make a first-time user stop. Model names are raw log identifiers (`claude-opus-5-5`, `claude-fable-5-1`, `claude-opus-5`), while the rest of the app says Fable 5 and Sonnet (MODELS-02). The dimmed small-sample rows fall to 2.5:1 in the light high-contrast appearance (MODELS-01).

The account page, Settings, and the add-account sheet render as designed in a test-process capture. The account page reports the Codex earned reset count as `2 resets · Expiry unknown`, while Home, the popover, and the menu say `2 available` with a known next expiry (ACCOUNT-06).

## Open findings

Ranked by severity, then surface order. Screenshot names refer to `.crit/2026-10-16-round1/captures/`. `render-*` captures come from a temporary test that put the real view controllers in an on-screen window in the test process (debug build, `--demo` fixture), deleted after capture. All other captures are of the packaged app.

### Severity 3

- **HOME-24** (observed and measured, krug.dont-make-me-think, nielsen.1, nielsen.8, design.principles.task-purpose) Once history exists, the forecast sits between Weekly Totals and the Account Usage table. The per-account answer and the whole reset calendar open below the window, and the toolbar period controls change content the user cannot see. **Measured:** dark-home-window.png, 1280 × 780 pt: Account Usage heading at 744 pt, no table row and no calendar row inside the window. Each provider forecast block is about 227 pt (four text rows and a 150 pt chart). **Doctrine:** the analytics plan decided "Home gains a forecast summary and chart above the reset calendar"; NATIVE-DESIGN.md says "The Account Usage table follows at its intrinsic height"; the baseline crit (HOME-01) moved the table up for this reason. **Fix:** order Home as Weekly Totals, Account Usage, Forecast, Reset Calendar, and record the order in NATIVE-DESIGN.md. Source: `Sources/AIUsageStats/HomeViewController.swift:126`.

### Severity 2

- **MENU-16** (observed, nielsen.4, nielsen.2, project.readings.identity-units-freshness) The menu bar number includes model-scoped weekly limits. A fully used Fable 5 limit would show Claude 0% while Home says the account is usable. The glance number disagrees with the general quota the user can still spend. **Measured:** dark-status-item-open.png shows Claude 51%. The same instance's menu (dark-menu-menu.png) shows personal 5-hour 99% left, Weekly 75% left, Weekly · Fable 5 51% left, and studio 100% in every window. **Doctrine:** NATIVE-DESIGN.md counts "every current window measured" for the status item, but says "a full model-scoped limit restricts only that model and adds nothing" for usability. **Fix (owner decision):** count only the general 5-hour and weekly windows in `AccountQuotaSummary.lowestCurrent` and `lowestLastKnown`, whose only caller is the status item, as `AccountUsability` already does. Keep the window name in the tooltip and record the rule. Source: `Sources/UsageCore/AccountQuotaSummary.swift:60`, `Sources/AIUsageStats/ApplicationDelegate.swift:116`.
- **HOME-27** (measured, appearance.color.legibility, data.chart-legibility; also Models) With the graphite accent, the forecast lines draw below the 3:1 graphic minimum in the increased-contrast appearance, which is the setting a user picks for more contrast. The lines are the only on-screen form of the history. **Measured:** contrast-home-window.png, history and projection lines #A8A8A8 on #FFFEFF = 2.36:1, axis labels #929292 = 3.10:1. Dark: #9D9D9D on #272B3A = 5.20:1. Models bars #A8A8A8 on the #EAEAEA track, about 2.0:1. **Fix:** draw the history and projection with `Color.primary` instead of `Color.accentColor`, and give the Models bars the same color. Source: `Sources/AIUsageStats/HomeForecastView.swift:167,176`, `Sources/AIUsageStats/ModelsView.swift:120`.
- **HOME-28** (needs device test, accessibility.keyboard-focus) Home's readings appear only after accounts load, and `showHome` never recalculates the key view loop. `showModels`, `showSettings`, and the account page do. Tab may never reach the forecast range pop-up, the table, or the calendar events. **Measured:** in the test-process window with keyboard navigation on (`AppleKeyboardUIMode` 2), 12 `selectNextKeyView` calls on Home stayed on the sidebar. The account page cycled sidebar, Manual balance disclosure, sidebar. **Doctrine:** "Tab reaches the table and events after it." **Fix:** recalculate the window's key view loop when Home's readings become visible (`HomeViewController.render` when `showsReadings` changes), then confirm Tab in the packaged app. Source: `Sources/AIUsageStats/AccountsWindowController.swift:256-266`.
- **HOME-30** (observed, nielsen.1, nielsen.4) A sign-in-required row shows `Not refreshed` in Updated and drops the time of its last known values, so the user cannot tell how old those numbers are. Three other branches still print the retired `No reading`. **Measured:** dark-home-states-window.png, studio@ row: quota cells `Last known 100% left`, Updated `Not refreshed` with no time. **Doctrine:** Vocabulary "Old reading … `Stale · last read 11:09`", and `No reading` is in the Do not use column. **Fix:** show the last read time for sign-in-required rows, and replace `No reading` with `Observation time unknown` or `Unavailable` as the vocabulary table says. Source: `Sources/AIUsageStats/HomeInterfaceFormatting.swift:819-833`.
- **MODELS-01** (measured, appearance.color.legibility) Halving the opacity of a whole row puts small-sample model names below 4.5:1 and their counts as low as 1.6:1. The page asks the user to judge exactly these rows. **Measured:** contrast-models-window.png, dimmed name #A3A3A3 on white 2.49:1, detail #CACACA 1.63:1. dark-models-window.png, name #909198 on #272B3A 4.49:1, detail #6F7079 2.86:1. Undimmed names are 12.49:1 and 10.99:1. **Fix:** dim only the bar and draw the row text in secondary label color, or keep text opacity at 0.7 or more. Source: `Sources/AIUsageStats/ModelsView.swift:88,167`.
- **MODELS-02** (observed, nielsen.2, nielsen.4, krug.dont-make-me-think) Models shows raw log identifiers. The user must map `claude-fable-5-1` to the `Fable 5` limit on Home, and tell `claude-opus-5-5` from `claude-opus-5` by hyphenated suffixes. **Doctrine:** "One name per concept in every surface." **Fix:** format a display name from the identifier: drop the provider prefix and join version digits with dots (`Opus 5.5`, `Fable 5.1`, `Opus 5`). Keep the raw identifier in the tooltip and accessibility value. Source: `Sources/AIUsageStats/ModelsView.swift:83,160`.
- **ACCOUNT-06** (observed, nielsen.4) The account page formats the earned reset count as a generic credit. It says `Expiry unknown` one row above a grant that expires tomorrow, while Home and the menu give the next expiry. **Measured:** render-account2-top-1-L0.png, Codex personal: `Earned resets  2 resets  Expiry unknown`, then `Example reset grant  Unknown  Expires in 1d 0h`. The Home table and popover for the same account say `2 available` and `Next expires Oct 17`. **Doctrine:** Vocabulary "Earned resets, value `2 available`, timing `Next expires in 12d`." **Fix:** add one shared earned-resets summary to `InterfaceFormatting` and use it for the account page row; the menu can adopt it after both lanes merge. Source: `Sources/AIUsageStats/AccountDetailViewController.swift:436`, `Sources/AIUsageStats/InterfaceFormatting.swift:139-140,164`.

### Severity 1

- **MENU-15** (source, menu.commands.grouping) While the window is open the app menu has Refresh All, Open AI Usage Stats, Settings…, and Quit, but no About AI Usage Stats, Hide (Command-H), Hide Others, or Show All. The Window menu has Minimize only. **Fix:** add those items to the main app menu only (not the status menu) and Zoom to the Window menu. Source: `Sources/AIUsageStats/ApplicationDelegate.swift:555-581`.
- **HOME-25** (observed, nielsen.4) The forecast introduces "pool" and "Last seen" for what the page already calls the weekly total and Updated. The popover says `Next expiry` where every other surface says `Next expires`. **Fix:** use `Weekly total reaches 0%` and `Updated` (or drop the per-account Last seen rows, which repeat the table), use `Next expires` in the popover, and add the forecast terms to the vocabulary table. Source: `Sources/AIUsageStats/HomeForecastModel.swift:210,227,252`, `Sources/AIUsageStats/HomeInterfaceFormatting.swift:671`.
- **HOME-26** (observed, layout.native-adaptation) At the 1020 × 640 pt minimum, about 99 pt day columns, the identity and scope fields shrink below the width of an ellipsis. They draw a fragment of a letter (`0% left · ı`), and a weekly reset (`09:42 ·…`) cannot be told from a 5-hour reset without hover. **Fix:** hide a scope or identity field, with its separator, when it cannot fit one character and an ellipsis; extend the minimum-width calendar test. Source: `Sources/AIUsageStats/UsageCalendarView.swift:688-700`.
- **ACCOUNT-07** (observed, nielsen.8) The fixed 108 pt value column breaks `0% left, Limit reached` after the comma. A never-read account repeats `Usage` as heading and row label (`Usage  Unavailable`). **Fix:** let the value column fit its widest value, or break before the state word without the comma as Home does; label the no-reading row `Status`. Source: `Sources/AIUsageStats/AccountReadingView.swift:24`, `Sources/AIUsageStats/AccountDetailViewController.swift:418`.
- **MODELS-03** (measured, data.chart-legibility) Each block sizes its bar track from its own text columns. The same share draws at different lengths in neighboring blocks, so the fixed 0 to 100 percent scale does not compare across blocks. **Measured:** left-column tracks Requests 237 pt, Steps per turn 258 pt, Responses with parallel tool calls 220 pt, Mean shell command length 253 pt. **Fix:** give every bar one fixed width. Source: `Sources/AIUsageStats/ModelsView.swift:79-93,124`.
- **MODELS-04** (observed, writing.labels-errors) Titles and details use abbreviations a reader must decode: `tok/s`, `chars`, `p90`, `JS`. **Fix:** `tokens per second`, `characters`, `90th percentile`, `JavaScript`. Source: `Sources/AIUsageStats/ModelsView.swift:248,282,297,309`.

## Correct as designed

- The gap in the forecast history line between Thu and Fri is a real history gap; the doctrine keeps gaps as gaps.
- At the default width, calendar events keep the whole time, scope, percentage, and short identity; identity tails truncate with an ellipsis.
- The populated status menu is 842 pt tall with four accounts and fits the 1329 pt screen. Smaller screens are untested.
- Weekly Totals rows in the menu omit the account that Home names beside Next reset; the tooltip names it.
- The account page subtitle `Claude` under `Claude · personal@example.invalid` repeats the provider only when two accounts share an email; elsewhere it is the only provider label.
- The inline Python block uses four colors, but every share is also printed as text, so color is not the only carrier.
- Models has no controls, so focus stays in the sidebar, as documented.
- A single Startup row on a large Settings page is the documented scope.
- Gray status menu section headers remain the documented native exception.
- Disabled Refresh All, Reconnect…, Connect API Credits…, and add buttons are demo behavior.

### Severity 2

- **HOME-31** (measured, nielsen.1, krug.dont-make-me-think, design.principles.task-purpose) With history recorded, the whole Reset Calendar sits below the default window, and the toolbar period controls change content the user cannot see. HOME-24's reorder fixed the per-account answer and left this part of its claim. **Measured:** Home document 1446 pt in a 780 pt window; Reset Calendar heading at about 1099 pt, 319 pt below the window bottom (render-dark-home-bottom-1.png). In the packaged dark-home-window.png no calendar row is visible. **Doctrine:** NATIVE-DESIGN.md "Home order: Weekly Totals, Account Usage, Forecast, Reset Calendar" and "Period commands reach the visible page through the responder chain." **Fix:** when Previous, Next, Today, Month, 2 Weeks, or their View menu commands run, scroll the Reset Calendar heading to the top of the visible area. Leave the section order alone. Source: `Sources/AIUsageStats/HomeViewController.swift:427` and the period length action near line 483.

## Keyboard paths reached

The test process window was never key (the test process is not the active app), so synthesized Tab and Escape events sent to the main window did nothing, and that result is not evidence. The checks below used AppKit's own key view calls or a key sheet.

- Home: `selectNextKeyView` from the sidebar goes to Account usage, Forecast range (`Next 7 days`), then the calendar events in order. Full keyboard access was on (`AppleKeyboardUIMode` 2).
- Account page (Claude personal): Sidebar, the Manual balance disclosure, the Billing toolbar button, Sidebar. Connect API Credits… and Refresh Account are disabled in demo, so they are correctly absent.
- Settings: focus lands on Launch at login.
- Add-account sheet: focus lands on the Provider pop-up; Escape sent to the sheet closed it and focus returned to the sidebar.
- Popover: Return on a focused event opened it with View Account focused. Escape on the popover is untested for the reason above.

## Correct as designed

- Secondary text measures #929292 on white (3.11:1) in light and with `--increase-contrast`, in AppKit and SwiftUI alike, including chart axis labels and Models footnotes. It is the system secondary label color, and the app flag does not establish the real Increase Contrast preference.
- The status menu follows the dark system menu bar when the app window is forced light (`-NSRequiresAquaSystemAppearance YES`); menus take the menu bar's appearance.
- The Models lower part, the Codex section and the inline Python breakdown, prints every share as text beside the four colors, so color is not the only carrier.
- The forecast history gap between Thu and Fri is a real gap in the demo history.
- The account page subtitle `Codex · Pro` and the title identity match the sidebar row.
- `Error: Fictional demonstration data.` on healthy demo accounts comes from the fixture's detail text.
- Disabled Reconnect…, Refresh Account, Refresh All, Connect API Credits…, and the add buttons are demo behavior.

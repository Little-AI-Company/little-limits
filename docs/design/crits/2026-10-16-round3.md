## Open findings

Ranked by severity, then surface order. Screenshot names refer to `.crit/2026-10-16-round3/captures/`. `render-*` captures come from a temporary Swift Testing test that put the real `AccountsWindowController` on screen in the test process (debug build). It selected the fixture by passing `--filter --demo-home` or `--filter --demo-reading-states` to `swiftpm-testing-helper`, so `CommandLine.arguments` held the fixture flag, and it set the dark, aqua, or high-contrast aqua appearance on `NSApp`. The test was deleted after capture. All other captures are of the packaged app.

### Severity 1

- **ACCOUNT-07** (observed, carried from round 1) See the recheck table. **Fix:** omit the row label when the only usage row is the unavailable summary, and widen the label column or shorten the label so `OpenAI API credits` fits on one line. Source: `Sources/AIUsageStats/AccountDetailViewController.swift:418`.
- **ACCOUNT-11** (observed, nielsen.4, krug.dont-make-me-think, writing.labels-errors) The account page names two different commands for the same next step. The timed stale line says `Choose Refresh Account to read it again.`, while the unread line says `No usage reading yet. Choose Refresh All to read usage.`, the unavailable line says `Unavailable. Choose Refresh All to try again.`, and the stale line without a time says `Stale. Choose Refresh All to check usage.` On this page the only labeled refresh control is `Refresh Account`; Refresh All is the icon-only button beside it (render-dark-states-account4-top-1-NSWindow.png). **Doctrine:** NATIVE-DESIGN.md vocabulary: "Refresh one account: `Refresh Account` (Shift-Command-R) on the account page." **Fix:** the account page state lines name Refresh Account; Home keeps Refresh All. Source: `Sources/AIUsageStats/AccountDetailViewController.swift:420,471,479,492`.
- **MODELS-03** (measured, carried from round 1) See the recheck table. **Fix:** one fixed track width for every block in a column. Source: `Sources/AIUsageStats/ModelsView.swift`.
- **MODELS-04** (source, carried from round 1) See the recheck table. **Fix:** `tokens per second`, `characters`, `JavaScript`, and `90th percentile` in visible text.
- **SETTINGS-02** (measured, layout.native-adaptation) The `App icon:` label sits about 4 pt above the title of its pop-up button. The Startup row aligns its label with the checkbox title, so the two rows of the same form disagree. **Measured:** cap tops at 2x in dark-settings, light-settings, and night-settings captures: `Startup:` 158 px and `Launch at login` 158 px; `App icon:` 272 px and `Night` or `Enamel` 280 to 281 px. **Cause:** the grid places every cell at the row top (`yPlacement = .top`), and the pop-up title is inset inside its 24 pt bezel. **Fix:** align the form rows to the first baseline (`NSGridView.rowAlignment = .firstBaseline`), keeping the note under the pop-up. Source: `Sources/AIUsageStats/GeneralSettingsViewController.swift:43-50`.

MENU-15 stays unverified at runtime (see the recheck table) and is not counted as open.

## What changed since round 2

**Limits Left name.** Every captured string uses the new name: the status menu (`Open Limits Left`, `Quit Limits Left`) in all four fixtures, the app menu title, About (`Limits Left`), the load failure page (`Limits Left could not read its saved account list.`), Settings (`Limits Left starts when you open it.`, VoiceOver label `Launch Limits Left at login`), and the App icon note. The bundle shows `CFBundleName` and `CFBundleDisplayName` `Limits Left`, and `CFBundleIconFile` `AppIcon`. Window titles are page names (Home, Models, Settings, account identity), as before. `AI Usage Stats` remains only in the data folder path and the Keychain service name, which #53 kept on purpose.

**App icon setting.** One native pop-up button, 24 pt tall, under `App icon:`, with Enamel and Night, each item showing its 16 pt icon. The note under it reads `Changes the icon in the Dock and app switcher while a Limits Left window is open, and in About Limits Left. Finder keeps Enamel.` It names what changes and what does not, in plain words, and measures 14.94:1 on white and 11.74:1 in dark. The key view loop from Settings is Launch at login, App icon, Sidebar, then back (`selectNextKeyView`, full keyboard access on). Source gives the pop-up the VoiceOver label `App icon` (`GeneralSettingsViewController.swift:68`); the selected item title supplies the value. With `-AppIconChoice night` the pop-up shows Night selected, and `defaults read com.parkerrex.ai-usage-stats AppIconChoice` afterwards reports no key, so the demo did not save the choice. Layout defect: SETTINGS-02.

**About panel.** night-settings-window.png shows the Night icon and dark-settings-window.png shows Enamel, each above `Limits Left` and `Version 0.2.0 (3)`. The panel takes the icon from `NSApp.applicationIconImage` (`ApplicationDelegate.swift:279`).

**Home calendar reveal.** See HOME-31. The page jumps to the calendar without animation, which fits the quiet interface rule. At the page end the heading stops where the scroll ends (477 pt in a 780 pt window), so the whole calendar shows rather than the heading at the top. The account filter does not scroll, because it also changes the table near the top. At 1020 pt the Month and 2 Weeks group collapses into one `2 Weeks` pop-up in the toolbar.

**New wording.** `Usage rate`, `Weekly total reaches 0%`, `Updated`, `Next expires`, `Last known 2 available`, `Choose Refresh Account to read it again.`, and `Status:` for a stale explanation all read correctly in captures. No em dashes were found in captured text.

## Correct as designed

- At 1020 pt a calendar event shows the provider symbol, time, and remaining percentage only; scope and identity move to the tooltip, accessibility label, and popover. This is the HOME-26 fix and its doctrine.
- After Next, the next two weeks read `No reported resets in this period.` The calendar shows reported reset events only, and the demo has none after Oct 25.
- Each forecast block has two `Updated` rows, one per account, told apart by the account name in the third column.
- Home's attention lines say `Choose Refresh All` while the account page should say `Choose Refresh Account` (ACCOUNT-11): Home's toolbar has Refresh All only.
- The Night icon's dark tile on the dark About panel has low edge contrast. That is the chosen artwork, not a layout defect.
- `AI Usage Stats` in the data folder and the Keychain service name is kept on purpose (#53). A Keychain permission prompt could show the old service name; that prompt was not exercised.
- The About panel has no copyright line, because `Info.plist` has no `NSHumanReadableCopyright`.
- Disabled Reconnect…, Refresh Account, Refresh All, Connect API Credits…, the add buttons, and `Error: Fictional demonstration data.` on healthy demo accounts are demo behavior.
